# Network Forensics Commands and Filters

Commands and Wireshark filters for examining a supplied educational packet capture, recovering an apparent image download, and reviewing related TLS evidence.

**Main finding:** `444444.png` was presented as `image/png`, but its content was identified as a PE32 Windows executable.

## Scope and handling

- The capture was supplied for educational analysis. The repository owner's contribution is the investigation and interpretation, not creation of the capture.
- Examine a working copy and preserve the original.
- Use a lab VM for extraction. The capture contains recoverable executable content. Do not run the exported file or visit the recorded endpoints.
- The addresses and certificate names below are historical observations. They do not describe current endpoint ownership or activity.
- Wireshark filters go in the display-filter bar. Bash and Python commands run in a Linux terminal.

## 1. Prepare a working copy

These examples assume the capture is named `investigation.pcap` and is in the current directory. Replace that name with your actual filename, such as `A2_q3.pcap`.

```bash
mkdir -p ~/pcap-investigation/{original,working,extracted}
cp investigation.pcap ~/pcap-investigation/original/
cp ~/pcap-investigation/original/investigation.pcap ~/pcap-investigation/working/
sha256sum ~/pcap-investigation/original/investigation.pcap \
          ~/pcap-investigation/working/investigation.pcap
```

**Purpose:** Create an analysis copy and compare its SHA-256 hash with the original. Matching hashes support byte-for-byte equivalence. They do not establish how the original capture was acquired.

Open the working copy using **Wireshark → File → Open**. Use **Statistics → Capture File Properties** to review its packet count and duration. For this capture, the count is **74,404 packets** and the duration is approximately **2 hours, 42 minutes, 55 seconds**.

## 2. Review HTTP requests

```wireshark
http.request
```

**Purpose:** Display decoded HTTP requests and review methods, paths, and endpoints before narrowing the investigation.

## 3. Find possible image downloads

```wireshark
http.request && (
    http.request.uri contains ".png" ||
    http.request.uri contains ".jpg" ||
    http.request.uri contains ".jpeg" ||
    http.request.uri contains ".gif" ||
    http.request.uri contains ".bmp" ||
    http.request.uri contains ".ico" ||
    http.request.uri contains ".webp"
)
```

**Purpose:** Find requests containing common image extensions.

**Observed result:** One request for `444444.png` and two for `/favicon.ico`.

**Limit:** This is a case-sensitive substring search. It can miss other spellings and extensionless files. An image extension does not establish the actual file type.

An additional check for server-declared image responses is:

```wireshark
http.response && http.content_type contains "image/"
```

**Purpose:** Search by declared MIME type instead of the request filename. A server can supply misleading metadata. Neither filter reveals encrypted HTTP content without decryption.

## 4. Isolate the candidate request

```wireshark
http.request.uri contains "444444.png"
```

**Purpose:** Locate the request for the candidate object and inspect its HTTP and TCP details.

| Field | Observation |
|---|---|
| Request frame | `2498` |
| Client | `10.1.29.101:49689` |
| Server | `5.61.27.159:80` |
| HTTP Host | `alphaenergyeng.com` |
| Requested path | `/wp-content/uploads/2020/01/ahead/444444.png` |
| User-Agent | `Haskel` |

Right-click the request and select **Follow → TCP Stream**. Record the stream number generated by Wireshark. If using the following filter, replace `N` with that numeric value:

```wireshark
tcp.stream == N
```

**Purpose:** Correlate both directions of one TCP connection. `N` is a placeholder, not a valid literal filter value.

The response supplied `200 OK`, `Content-Type: image/png`, and `Content-Length: 475136`.

## 5. Recover the HTTP object

Use **File → Export Objects → HTTP**. Select `444444.png` from `alphaenergyeng.com` and save it to `~/pcap-investigation/extracted/444444.png`.

**Purpose:** Recover the reassembled HTTP object rather than a single packet or a complete stream containing headers.

If export fails or the object is incomplete, document that limitation before drawing conclusions from the recovered bytes.

## 6. Check file size, format, starting bytes, and hash

```bash
cd ~/pcap-investigation/extracted
chmod a-x 444444.png
wc -c 444444.png
file 444444.png
xxd -l 64 444444.png
sha256sum 444444.png
```

| Command | Purpose |
|---|---|
| `chmod a-x` | Remove execute permission; this is not a complete containment measure. |
| `wc -c` | Measure file size for comparison with HTTP Content-Length. |
| `file` | Identify file format from its content. |
| `xxd -l 64` | Display the first 64 bytes without executing the file. |
| `sha256sum` | Calculate an identifier for the recovered bytes. |

**Checkpoints for the complete recovered body:**

| Check | Result |
|---|---|
| Size | `475136` bytes |
| File identification | `PE32 executable (GUI) Intel 80386, for MS Windows, 4 sections` |
| Starting bytes | `4D 5A` (`MZ`) |
| Expected PNG starting bytes | `89 50 4E 47 0D 0A 1A 0A` |

```text
SHA-256:
56ee803fa903ab477f939b3894af6771aebf0138abe38ae8e3c41cf96bbb0f2a
```

**Interpretation:** File content conflicts with the PNG filename and MIME type. Format identification and hashing do not establish execution or malware behaviour.

### Additional PE header verification

This optional check inspects the PE signature at the offset specified by the DOS header. It supplements the `file` result; it is not a full PE validation or malware detector.

```bash
python3 - <<'PY'
from pathlib import Path
import struct

data = Path("444444.png").read_bytes()
if len(data) < 64:
    raise SystemExit("File is too short for the header check.")

offset = struct.unpack_from("<I", data, 0x3c)[0]
if offset + 4 > len(data):
    raise SystemExit("PE offset is outside the recovered file.")

print("Starting signature:", data[:2])
print("PE header offset:", hex(offset))
print("PE signature:", data[offset:offset + 4])
PY
```

Expected output for this object:

```text
Starting signature: b'MZ'
PE header offset: 0x110
PE signature: b'PE\x00\x00'
```

## 7. Review encrypted connections

```wireshark
tls
```

**Purpose:** Display decoded TLS traffic across ports. Use **Statistics → Conversations → TCP**, with **Limit to display filter** enabled, to compare endpoints, ports, duration, and traffic volume.

```wireshark
ip.addr == 68.1.115.106 && tls
```

**Purpose:** Review decoded TLS activity involving the selected endpoint.

```wireshark
ip.addr == 68.1.115.106 && tcp.port == 49697
```

**Purpose:** Narrow the view to the selected connection between `10.1.29.101:49697` and `68.1.115.106:443`. A recorded TCP stream number can narrow it further if the port is reused.

## 8. Examine the Client Hello and SNI

```wireshark
ip.addr == 68.1.115.106 && tcp.port == 49697 &&
tls.handshake.type == 1
```

**Purpose:** Locate the selected Client Hello. Expand **Transport Layer Security → Handshake Protocol: Client Hello** and inspect its extensions.

**Observed result:** Frame `3173` has no `server_name` extension. The client supplied no hostname through SNI in this handshake.

**Limit:** Absent SNI does not independently establish malicious activity.

## 9. Check captured DNS answers

```wireshark
dns.a == 68.1.115.106
```

**Purpose:** Search decoded DNS A-record answers containing the selected IP address.

**Observed result:** No matching packets. No DNS A-record answer linking a hostname to this IP was found using this filter.

**Limit:** This does not prove that no domain exists. Resolution may have occurred outside the capture, used a cache, or used another method.

## 10. Inspect the server certificate

```wireshark
ip.addr == 68.1.115.106 && tcp.port == 49697 &&
tls.handshake.type == 11
```

**Purpose:** Locate the certificate message for the selected connection. Expand the leaf certificate's **issuer**, **subject**, and **validity** fields.

| Field | Observation |
|---|---|
| Certificate frame | `3174` |
| Subject Common Name | `gaevietovp.mobi` |
| Issuer Common Name | `gaevietovp.mobi` |
| Serial number | `0x0a83` |
| Signature algorithm | `sha256WithRSAEncryption` |
| Valid from | `2020-01-27 22:35:20 UTC` |
| Valid until | `2021-01-27 04:45:24 UTC` |

**Interpretation:** The certificate provides a name claim when SNI is absent. The capture date falls within the certificate's date range.

**Limits:** This does not establish trust-chain validity, operator identity, or malicious intent. Matching Common Names alone do not prove a self-signed certificate. The name came from the certificate, not DNS or SNI.

## 11. Compare event timing

```wireshark
frame.number == 2498 ||
frame.number == 3173 ||
frame.number == 3174
```

**Purpose:** Display the file request and selected TLS handshake together. Sort by frame number or time before recording the sequence.

| Frame | Relative capture time | Event |
|---|---:|---|
| `2498` | `107.866461 s` | Apparent PNG request |
| `3173` | `513.871330 s` | Client Hello |
| `3174` | `513.986818 s` | Server handshake and certificate |

The selected Client Hello follows the file request by approximately **406 seconds**. The same client and event order justify further investigation, but do not prove that the recovered executable initiated the connection.

## Conclusion

The evidence supports a Windows executable transferred under a PNG filename and MIME type. The later TLS connection contributes historical indicators, but the capture alone does not establish file execution, a malware family, encrypted commands, or a confirmed command-and-control relationship.
